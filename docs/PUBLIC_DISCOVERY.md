# Public discovery bundle

Discovery must expose reviewed substance, not working/review/private state.

The deterministic discovery projection is generated from `data/insights.json` using one hard boundary:

```text
status == published
```

Everything else is excluded from the discovery bundle even if it exists in the repository for review or local research.

## Generated surfaces

Run:

```bash
python scripts/build_discovery.py
python scripts/build_discovery.py --check
```

The generator writes:

- `/atom.xml` — Atom feed of published explainers;
- `/discovery.json` — compact machine-readable published-only manifest;
- `/llms.txt` — LLM-oriented navigation that points only to safe public projections.

`discovery.json` points to the published-only concept index and published knowledge-history feed rather than treating the full working registries as publication surfaces.

The existing sitemap is separately generated by `scripts/build_sitemap.py` from public records and substantial concept pages.

## OpenGraph

Generated explainer and concept pages already include:

- canonical URL;
- `description`;
- `og:title`;
- `og:description`;
- `og:type`;
- structured JSON-LD.

OpenGraph therefore describes existing evidence-backed pages rather than creating thin SEO landing pages.

## Review/private exclusion

`build_discovery.py --self-test` creates one published and one review-only fixture and asserts that review slug, title, source URL and summary do not appear in Atom, `llms.txt` or discovery JSON.

The private source overlay is physically under `.local/private/` and is not read by the discovery builder. `validate_private_overlay.py` separately rejects public-builder coupling to that overlay and scans public/versioned surfaces for private-only IDs.

## Synchronization

`.github/workflows/discovery.yml` rebuilds discovery + sitemap whenever published insight/source or public knowledge discovery inputs change.

On pull requests it fails on generated drift. On `main` it commits only the generated files when needed.

## Corpus gate

The discovery infrastructure can exist with a small corpus, but distribution should not be treated as product proof.

At the time this workflow was introduced, only one intentionally published explainer existed. Issue #38 remains the gate for a curated multi-source public proof corpus. RSS/SEO expansion should amplify reviewed substance only after that corpus exists; the presence of a feed is not itself a success metric.
