ReAct: reason, act, observe — then update the plan

ReAct interleaves model reasoning with external actions and observations so each can update the next step; it improves grounding but is not a production control layer.

WHY THIS MATTERS

ReAct is a useful mental model for the inside of an agent loop. It explains how a model can alternate between thinking and interacting with an environment, while making clear why a separate execution layer is still required for authorization, reliable side effects, recovery and audit.

KNOWLEDGE DELTA

What this source changes in the existing model.

ReAct does not replace the production control model; it clarifies a different layer: how a model updates its next action using reasoning and external observations.

MENTAL MODEL

01 · Reason

Thought

Compose useful context: decompose the goal, track progress, interpret evidence or reformulate the plan.

02 · Act

Environment action

Search, look up, navigate or perform another task-specific action that can change or query the environment.

03 · Observe

External feedback

The environment returns evidence or state that becomes new context rather than leaving reasoning closed over internal knowledge.

04 · Update

Next decision

The model uses the expanded trajectory to continue, reformulate, finish or choose another action.

Source problem

Reason-only trajectories can remain ungrounded and propagate hallucinated facts, while action-only trajectories can interact with an environment without enough high-level reasoning to plan, interpret observations or recover from mistakes.

Source thesis

Interleave language reasoning traces with task-specific actions and environment observations so reasoning guides acting while external feedback grounds and updates subsequent reasoning.

Core topics
  • Thought → Action → Observation loop
  • language reasoning as an augmented action space
  • internal knowledge versus external evidence
  • reason-only versus act-only trade-offs
  • loop, retrieval and context-length failure modes
  • action selection versus production execution control

EXAMPLES

knowledge retrieval

A question requires facts that are uncertain or absent from the model's internal context.

Can the model explicitly decide what to retrieve, use the returned observation, and revise the next step instead of completing a closed reasoning chain?

interactive task

An agent searches an environment for an object and then must switch from exploration to completing the goal.

Can sparse reasoning track progress and update the plan after observations rather than blindly emitting the next action?

production agent architecture

A ReAct-style loop proposes a consequential tool call such as changing business data.

What separate layer checks authority, executes idempotently, records evidence and verifies the outcome after the model selects the action?

WHERE THE MODEL BREAKS

Useful does not mean sufficient.

  1. ReAct can enter repetitive thought/action loops; an observation does not guarantee the model will reason its way out of a bad trajectory.
  2. Non-informative retrieval can derail subsequent reasoning, making tool quality and observation design part of agent quality.
  3. Complex tasks with large action spaces need more demonstrations and can hit in-context length limits under the paper's prompting setup.
  4. The paper's benchmark action spaces are constrained and intentionally safe; connecting an LLM to real external actions introduces risks the paper does not solve.
  5. Visible reasoning traces improve diagnosability in this setup but should not be treated as a durable, complete or trustworthy audit record of production execution.

PERSONAL ACTION MAP

Convert understanding into a decision.

Use now
  • Separate two design questions when reviewing an agent: how does the model choose the next action, and how does the system control execution of that action?
  • Treat observations as first-class inputs to the next decision rather than simply tool outputs to display.
Try
  • Build a tiny read-only ReAct loop with one search/lookup tool, a strict maximum step count and an explicit repeated-state breaker.
  • Log Thought/Action/Observation as diagnostic development data, then compare it with the separate execution evidence you would need for a consequential tool call.
Learn
  • feedback-loop agent design
  • reason-only versus act-only trade-offs
  • observation/tool-result grounding
  • stagnation and loop detection
  • the boundary between model trajectory and controlled execution
Build
  • A minimal agent-loop demo where read-only retrieval is allowed directly but a simulated write action is handed to a separate policy/execution boundary.
Watch
  • How modern native tool-calling agents preserve the ReAct feedback principle while hiding or restructuring free-form reasoning traces.
Ignore for now
  • The paper's absolute 2022-era PaLM benchmark scores as a ranking of current agent systems.
