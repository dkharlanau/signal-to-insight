# Source, date & provenance policy

Signal to Insight is a commentary, research and explanation project, not a mirror of third-party material.

## Every source record must contain

- canonical source title;
- canonical URL or stable identifier;
- source type;
- creator / speaker / organization when known;
- publication date when independently verifiable;
- event date when the material comes from a conference/session;
- capture/access date;
- analysis/review date;
- version, duration or release when materially useful;
- a note explaining any date uncertainty.

Never infer or fabricate a publication date. If it cannot be verified, store `null` / `unknown` and retain the dates that are known.

## Supporting research

When the explainer uses material beyond the original source, record:

- title;
- URL;
- publisher/organization;
- why the source was used: verification / prerequisite / alternative / counterpoint / tool documentation;
- access date.

Prefer primary sources and official documentation for technical facts.

## Store

- source metadata and dates;
- original notes and derived analysis;
- concept and dependency maps;
- independently created diagrams and applications;
- tool/system references and official documentation links;
- short quotations only when they materially improve commentary;
- supporting or contradictory evidence;
- explicit distinctions between source claims and project-derived conclusions.

## Do not store publicly

- full third-party transcripts;
- copied articles or documentation;
- source media downloads;
- large excerpts that substitute for the original source;
- private personalization data that is unnecessary for the public explainer.

## Review questions

Before publishing an explainer:

1. Is the source clearly attributed?
2. Are publication/event/access/analysis dates recorded accurately?
3. Did we map the whole source before selecting content?
4. Is the selected material coherent rather than a list of isolated highlights?
5. Are source claims distinguishable from our interpretation and enrichment?
6. Are missing prerequisites supplied where necessary?
7. Are important limitations or counterexamples visible?
8. Are tools/systems linked to primary documentation where practical?
9. Does the page lead to a useful action, learning decision or awareness decision?
10. Can the reader reach the original source directly?

The transformation target is:

**source → coherent model → verified context → personal action → visual explanation**

not:

**source → shorter source**.
