EXPLAINER / 001

Why enterprise AI agents fail after the POC

Source ↗

The hard part is not getting an agent to produce the right answer once. The hard part is making every action authorized, observable, reversible and reviewable inside a real organization.

SourceAI Engineer talk SpeakersChristopher Lovejoy
Saul Howard FocusProduction architecture

THE FALSE FINISH LINE

POC

Model → Data → API

Accuracy is high. Latency is acceptable. The demo works.

≠
PRODUCTION

Identity + Policy + Audit + Human + Replay

The organization must be able to explain and control the work.

FOUR PRIMITIVES

01

Execution history, not developer logs

Use an append-only event history as the system's source of truth. The goal is to reconstruct what the agent knew, what it accessed, what it decided and what happened next.

requestidentityreaddecisionapprovalaction
02

Separate orchestration from sensitive data

Observability should not require unrestricted access to business data. Keep event references and protected objects separate, then authorize access at the point of use.

↕ authorized reference

03

Human and AI are executors of the same task

Model the task independently from its executor. Then an uncertain or policy-sensitive step can move to a human without creating a separate exception workflow.

approve_change(context)
AI agentHuman steward
04

Replay turns production history into evals

If system state is reconstructable, a new model, prompt, policy or tool can be tested against historical cases while changing one component at a time.

case t₀→old model / A case t₀→new model / B

APPLICATION

SAP customer-master change

A useful test is whether the architecture can answer a question months later: Why was this customer changed, under whose authority, using which context, and with which approval?

Change request↓ Identity + authority↓ Agent proposal↓ Policy → AI / Human↓ SAP / MDG action↓ Verification + ledger

WHERE THE TALK OVERSIMPLIFIES

The primitives help. They do not remove the hard engineering.

Auditability
An immutable log still needs identity, policy versions, retention, tamper protection and meaningful event semantics.

Zero trust
Separating data and orchestration reduces exposure; it does not automatically eliminate prompt injection or data exfiltration.

Human handoff
Executor equivalence still needs ownership, locking, idempotency, approval authority, timeout and recovery rules.

THE DURABLE INSIGHT

Don't bolt enterprise controls onto an AI demo. Build an execution substrate where both humans and agents can perform controlled work.
